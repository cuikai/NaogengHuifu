# 脑梗恢复 · 微信小程序

AppID：`wxdea4df1878353cea`

## 怎么跑起来

1. 微信开发者工具 → 导入项目 → 目录选 `miniprogram/`
2. AppID 已经写在 `project.config.json` 里，不用改
3. 不需要装依赖、不需要构建，直接就能预览

没有后端、没有网络请求、不采集任何数据。所有记录用 `wx.setStorage` 存在用户自己的手机上。

## 页面结构

进去先是一屏入口，四个模块各管一件事 —— 避免一屏塞下全部内容。

```
pages/index     首页：第几天 + 昨天的回声 + 四个入口
 ├ pages/today    今天要做的（照护 5 件 + 让他自己做的 4 件）
 │                全部完成 → 完成态：给照护者一个「下班」的时刻
 ├ pages/train    今天的训练（8 个动作，按「组」计数）
 │   └ pages/move   单个动作：动画 + 剂量 + 步骤 + 什么时候必须停
 ├ pages/know     请一定要知道（10 条）
 │   └ pages/card   单张知识卡：对错对比图 / 图示 / 要点 / 出处
 └ pages/record   记录：第几天、累计、里程碑、你写下来的话
pages/about     内容出处、我们刻意不做的三件事、清空记录
```

## 数据都在 utils 里

| 文件 | 内容 |
|---|---|
| `utils/data.js` | 今天要做的两组事 + 统一的「什么时候必须停」 |
| `utils/moves.js` | 8 个训练动作：剂量、步骤、目标组数 |
| `utils/cards.js` | 10 张知识卡的全文 |
| `utils/milestones.js` | 改良 Barthel 指数的 10 个条目 |
| `utils/store.js` | 本地状态：跨天结算、计数、累计、里程碑 |

改内容只动这几个文件，不用碰页面。每一条剂量和数字的出处见 [`docs/`](../docs)。

## 图怎么来的

所有插图的源文件是 SVG，仍然维护在 [`web/index.html`](../web/index.html) 里 —— 那是唯一的真相来源。

- **静态说明图** → 直接导出成 `images/s/*.svg`
- **训练动作动画** → 小程序的 WXML 不能内联 SVG，用 `<image>` 引入的 SVG 也不会播 SMIL 动画。
  所以把动画逐帧渲染后压成 GIF（`images/mv/*.gif`，40 帧，`gifsicle -O3 --lossy=40`）。
  GIF 在 `<image>` 里能正常播放，8 个加起来约 570 KB。

导出脚本在仓库外的构建目录里，改完 SVG 需要重新导一次。

## 不同分辨率

- 布局一律用 `rpx`，按屏宽等比。
- 但 `rpx` 在小屏上会把正文缩到看不清 —— 对老年用户是硬伤。
  所以 `app.js` 会按屏宽算一个字号系数写进 `--fs`，小屏放大一点、大屏收一点，
  让正文的**物理大小**在各种手机上接近一致。所有字号写成 `calc(32rpx * var(--fs))`。
- 图片用 padding-top 百分比撑出固定比例，不依赖 `aspect-ratio`，老设备也不会跳版。
- 底部留了 `env(safe-area-inset-bottom)`。

已在 320 / 375 / 414 三种宽度下逐页核过版式。
