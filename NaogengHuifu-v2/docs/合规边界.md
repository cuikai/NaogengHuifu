# 合规边界

一句话：**这是一个照护与训练的辅助工具，不是医疗器械，不做医疗判断。**

## 四条不可越的线

1. **不做诊断。** 不推断病因、不判断病灶、不解释影像和化验。
2. **不生成治疗方案。** 对外一律叫「今天适合练的」「按你勾的情况筛出来的」，**不用「处方」「方案」「疗程」**。
3. **不评估疗效。** 不算分、不分级、不出结论、不画「恢复百分比」。
4. **不做在线问诊。** 没有医生入口、没有咨询、没有转诊撮合。

## M/H 分层为什么可以存在

内部维护移动能力（M）和上肢手功能（H）两根轴，**只用来筛内容**：

- 界面上不出现任何数字或分级名称。用户看到的是「能站起来，走还不稳」这样的**事实描述**，不是「3 级」。
- 切分点是产品设计，不对应任何标准量表的分级。不要在文案里暗示它等价于 Brunnstrom、Fugl-Meyer 或任何评定量表。
- 措辞一律是「按你勾的情况筛出来的」，不是「你的分级是」。

`utils/milestones.js` 的立场同理：里程碑条目取自改良 Barthel 指数的 10 个条目，但**只记「他哪天第一次做到了」**，不算分。一旦算分，它就变成功能评定 —— 那是医疗判断。

## 「记录」页的趋势曲线

只画三道能力题的合计值随时间的变化，用于让家属看到方向。它：

- 不叫「评分」「得分」，标题是「能力趋势」；
- 不与任何常模比较，不出现「正常范围」；
- 满档常数写在 `assess.TREND_MAX`，页面不得另写一个数（v2.1 修过一次：页面写死 12，实际满档 11，柱子永远顶不到头）。

## 安全兜底的三层

这三层是这个产品能不能上线的底线，不是可选项：

| 层 | 在哪 | 干什么 |
|---|---|---|
| 分层封顶 | `assess.levelM` | 家属勾选互相矛盾时**一律取低的那一层**。判低了只是内容简单一点，判高了是让站不稳的人做单腿站立 |
| 标记屏蔽 | `assess.FLAG_RULE[].block` | 勾了肩膀疼就拿掉肩前屈上举；勾了摔倒过就拿掉单腿站立 |
| 就医分诊 | `FLAG_RULE[].urgent` / `adl.CALL` | 有一档情况不是「注意一点」，是「今天别练，去医院」。它必须和普通注意事项**在视觉上分开**，否则会被一起划过去 |

## 每一条剂量都要能指回出处

见 `docs/证据与来源.md` 和 `utils/evidence.js`。规矩：

- 能核到指南的写指南，写到推荐意见编号和证据等级；
- 属于常规实践的**明说是常规实践**；
- 证据本身弱的**把弱说出来**。

把常规实践说成指南推荐、把弱证据说成强证据，比不写更糟 —— 家属会据此做决定。

## 隐私

- 全部数据存在本机（`wx.setStorageSync`），不上传任何服务器。
- 不采集用户信息，不含支付、不含广告、不含任何第三方 SDK。
- 后台的「用户隐私保护指引」仍需按微信的流程填写。
- 「清空全部记录」在 `pages/about`，二次确认后不可恢复。

## 提交审核

- 类目按微信当时的要求填。本项目不做诊断、不生成治疗方案、不评估疗效，也不提供在线问诊。
- 文案里不要出现「治疗」「康复方案」「疗效」「有效率」这类词。
- 医学内容须有康复治疗师逐条签字留档，见 `docs/上线前检查清单.md`。
