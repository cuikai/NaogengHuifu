# 脑梗恢复 · 微信小程序 v2

AppID：`wxdea4df1878353cea`

## 这一版改了什么

v1 的所有人拿到的是同一份内容 —— 8 个训练动作全是床上做的（踝泵、握拳、屈肘、屈膝、桥式…），
「今天要做的」固定是喂饭 / 翻身 / 吃药。**一个已经能自己走路的患者进来，一条都用不上。**

v2 的主线是：**先弄清楚他现在能做到什么，再决定今天练什么。**

```
第一次打开 → pages/assess    3 分钟 8 道场景题
           → pages/profile   能力画像（两根轴）+ 安全提示
           → pages/index     首页：今天练什么 / 今天让他自己做
              ├ pages/plan     今天的训练（按分层筛出来的 4~5 个）
              │  └ pages/move    动作页：骨骼动画 + 计数 + 练完的三档反馈
              ├ pages/today    今天让他自己做（按分层换内容）
              ├ pages/know     请一定要知道 → pages/card
              └ pages/record   能力趋势 + 第一次做到
```

## 双轴分层

卒中后上下肢恢复常常不同步 —— 很多人能自己走，患手却还握不住杯子。
所以内部维护两根轴，训练内容按两根一起筛：

| 层 | 移动能力 M | 上肢手功能 H |
|---|---|---|
| 1 | 还起不来，主要在床上 | 患手还动不了 |
| 2 | 能坐住了，还站不起来 | 手能动，抬不起来 |
| 3 | 能站起来，走还不稳 | 能抬起来，还握不住 |
| 4 | 能走了，但还不够稳 | 能拿住大件东西 |
| 5 | 日常基本能自理 | 能做精细动作了 |

**M/H 只存在于代码里，界面上不出现任何数字或分级。** 见「合规边界」。

| 文件 | 内容 |

| `utils/poses.js` | **动作库：每个动作的关节角度关键帧** —— 动画的唯一真相来源 |
| `utils/figure.js` | 骨骼渲染器（正向运动学 + Canvas 2D） |
| `utils/library.js` | 进阶阶梯与基础组数 |
| `utils/plan.js` | 今日训练组装 + 升降级算法 |
| `utils/adl.js` | 「今天让他自己做」按分层筛 + 统一的停止信号 |
| `utils/cards.js` | 10 张知识卡的全文 |
| `utils/milestones.js` | 改良 Barthel 指数的 10 个条目 |
| `utils/store.js` | 本地状态：分层、每日反馈、升降级进度、每周趋势（v1 数据自动迁移） |

改内容只动这几个文件，不用碰页面。

## 动画：不再画图

v1 的 8 个动作是 8 张手工维护的 SVG，逐帧渲染压成 40 帧 GIF，共 570 KB。
改一个动作要重导一次，所以动作数量扩不动、品质也参差。

v2 是**一个渲染器 + 每个动作一份关节角度关键帧**：

- 新增一个动作 = 在 `utils/poses.js` 里加约 40 行 JSON，**包体不增加**
- 品质天然统一，不会一个动作精细一个粗糙
- 能叠加视频拍不出来的信息层：高亮该发力的关节、画出运动轨迹、正视图上画重心垂线
- **标准动作和常见代偿可以并排同步播**（`compare` 字段）—— 这是康复里最值钱的一件事
- 速度可调、患侧可左右镜像

组件是 `components/figure`，用 `<canvas type="2d">` + `canvas.requestAnimationFrame`。

```
<figure move="sit-to-stand" speed="{{0.5}}" mirror="{{true}}" cmp="{{false}}" bindtick="onTick" />
```

角度约定写在 `utils/figure.js` 头部注释里。躯干/头从「正上方」量起，四肢从「正下方」量起，
正方向 = 人物面朝的方向。`anchor` 指定哪个关节钉在地面/床面上，所以脚不会浮空也不会陷进去。

**还没做的：** 手部精细动作（握拳伸展、捏取）需要单独的手部绘制器，`images/mv/*.gif` 里的
`grip.gif` / `wrist.gif` 暂时保留，等手部渲染器做完再删。

## 升降级

练完每个动作要回答一句：**很轻松 / 有点吃力 / 做不到或疼**。

- 连续 2 次「很轻松」→ 先加组数；加到上限再升一档（阶梯见 `utils/library.js` 的 `LADDER`）
- 「有点吃力」→ 保持
- 「做不到或疼」→ 当场减组数或退一档；连续 3 天 → 提示就医

阶梯顺序是有讲究的：**先加量（安全），再减支撑（难度真正上升），最后才加幅度和速度。** 反过来做容易摔。

## 合规边界

v1 的 `utils/milestones.js` 写着「不算分、不分级、不下结论 —— 那属于功能评定，是医疗判断，
软件不能做」。**这个立场 v2 原样守住**，新增的快筛不能把它破掉：

- 界面上不出现分数、不出现分期。M/H 只用来筛内容
- 措辞是「按你勾的情况筛出来的」，不是「你的处方是」
- 不评估疗效、不做在线问诊、不生成治疗方案
- 每条剂量仍然标注公开指南出处

**上线前必须做的一件事：** 动作库、剂量、停止信号、代偿判定，要有康复治疗师逐条过一遍并签字留档。
v2 新增了站立与步行内容（v1 刻意回避了这块），跌倒风险必须由专业人把关。
`pages/about` 里写清楚了这部分的四个前提条件。

## 不同分辨率

（这一套 v1 做得很扎实，原样保留）

- 布局一律用 `rpx`，按屏宽等比
- `app.js` 按屏宽算字号系数写进 `--fs`，小屏放大、大屏收一点，让正文的**物理大小**接近一致；
  所有字号写成 `calc(32rpx * var(--fs))`
- 图片用 padding-top 百分比撑比例，不依赖 `aspect-ratio`
- 底部留了 `env(safe-area-inset-bottom)`
