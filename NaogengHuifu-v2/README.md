# 脑梗恢复 · 微信小程序 v2

AppID：`wxdea4df1878353cea`

## 这一版改了什么

v1 的所有人拿到的是同一份内容 —— 8 个训练动作全是床上做的（踝泵、握拳、屈肘、屈膝、桥式…），
「今天要做的」固定是喂饭 / 翻身 / 吃药。**一个已经能自己走路的患者进来，一条都用不上。**

v2 的主线是：**先弄清楚他现在能做到什么，再决定今天练什么。**

```
第一次打开 → pages/assess    3 分钟 8 道场景题
           → pages/profile   能力画像（两根轴）+ 安全提示
           → pages/index     首页：今天练什么 / 今天让他自己做
              ├ pages/plan     今天的训练（按分层筛出来的 4~5 个）
              │  └ pages/move    动作页：骨骼动画 + 计数 + 练完的三档反馈
              ├ pages/today    今天让他自己做（按分层换内容）
              ├ pages/know     请一定要知道 → pages/card
              └ pages/record   能力趋势 + 第一次做到
```

## 双轴分层

卒中后上下肢恢复常常不同步 —— 很多人能自己走，患手却还握不住杯子。
所以内部维护两根轴，训练内容按两根一起筛：

| 层 | 移动能力 M | 上肢手功能 H |
|---|---|---|
| 1 | 还起不来，主要在床上 | 患手还动不了 |
| 2 | 能坐住了，还站不起来 | 手能动，抬不起来 |
| 3 | 能站起来，走还不稳 | 能抬起来，还握不住 |
| 4 | 能走了，但还不够稳 | 能拿住大件东西 |
| 5 | 日常基本能自理 | 能做精细动作了 |

**M/H 只存在于代码里，界面上不出现任何数字或分级。** 见「合规边界」。

## 动画：不再画图

v1 的 8 个动作是 8 张手工维护的 SVG，逐帧渲染压成 40 帧 GIF，共 570 KB。
改一个动作要重导一次，所以动作数量扩不动、品质也参差。

v2 是**一个渲染器 + 每个动作一份关节角度关键帧**：

- 新增一个动作 = 在 `utils/poses.js` 里加约 40 行 JSON，**包体不增加**（14 个动作 0 张图）
- 品质天然统一，不会一个动作精细一个粗糙
- 能叠加视频拍不出来的信息层：高亮该发力的关节、画出运动轨迹、正视图上画重心垂线
- **标准动作和常见代偿可以并排同步播**（`compare` 字段）—— 这是康复里最值钱的一件事
- 速度可调、患侧可左右镜像

组件是 `components/figure`，用 `<canvas type="2d">` + `canvas.requestAnimationFrame`。

```
<figure move="sit-to-stand" speed="{{0.5}}" mirror="{{true}}" cmp="{{false}}" bindtick="onTick" />
```

### 角度写的是关节角，不是画布角

关键帧里的每个数字都是康复科口头说的那个角度，写数据的人不用在脑子里做坐标变换：

| 字段 | 含义 | 生理范围（渲染器强制） |
|---|---|---|
| `trunk` | 躯干前倾（世界角，0 直立，−90 平躺） | — |
| `neck` | 颈，+ 低头 | −32 ~ 46 |
| `hip` | 屈髋，+ 大腿抬向身前 | −26 ~ 132 |
| `knee` | 屈膝，+ 小腿向后折 | **0 ~ 146** |
| `ankle` | + 背屈（勾脚尖）/ − 跖屈（绷脚尖） | −46 ~ 28 |
| `sho` | 肩前屈，+ 手臂前举 | −58 ~ 176 |
| `elb` | 屈肘，+ 前臂向前折 | **0 ~ 150** |
| `wri` | 腕，+ 背伸 | −72 ~ 72 |

带 `F` 后缀 = 远侧那半边。**屈膝和屈肘的下限是 0**，所以数据写错也画不出向前反折的膝盖 —— 
`figure.js` 的 `LIM` 会把每个角度夹回生理范围。

三个让姿势自动符合物理的机制：

- `flat: 1` —— 这只脚平踩在支撑面上，踝角由其它关节反推。改屈膝屈髋时脚自动跟着对，
  不会出现「脚尖插进地里」或者「踮着脚坐着」。如果关节角度根本不允许平踩，体检脚本会报出来。
- `anchor` —— `ground` 骨盆横向固定（原地走）、`feet` 脚固定（提踵）、或某个关节名。
  纵向一律用最低的触地点落在支撑面上，所以骨盆的起伏（走路的上下、坐站的升起）是算出来的。
- `plant: 0→1` —— 横向参照物在「骨盆不动」和「脚不动」之间过渡。坐站转移正好要这个：
  坐着的时候屁股在椅面上不动、动的是脚往后收；离座之后改成脚不动、身体绕着脚起来。

道具的位置（扶手高度、椅面高度、杯子位置）不是估的，是解出来的 —— 
先解出手/脚的实际落点，再把道具放到那儿。所以「扶稳了」画出来手真的在横杆上，
「手撑椅面」画出来手真的按在椅面上。

### 时长要和文字对得上

阶段条上写「保持 5 秒」，动画就得真的停 5 秒 —— 患者是跟着动画数拍子做的，
说停 5 秒结果只停 2 秒，练的就是另一个剂量。所以 `cycle` 和关键帧的 `t` 是按
文字里的秒数排出来的，不是随手填的：

| 动作 | 周期 | 怎么排的 |
|---|---|---|
| 踝泵 | 7.8s | 勾 1.2 → 停 2 → 绷 1.6 → 停 2 → 回中 1.0 |
| 桥式 | 9.8s | 抬 2 → 保持 5 → 放下 2 → 落床 0.8 |
| 坐位伸膝 | 7.0s | 抬 1.5 → 停 3 → 慢慢放下 2.5 |
| 坐站转移 | 8.0s | 前倾 1.8 → 起立 1.6 → 站直停 2 → 坐回 2 → 落座 0.6 |
| 重心转移 | 11.5s | 每边真的停满 3 秒 |
| 提踵 | 5.2s | 踮 1.2 → 停 2 → 放下 2 |
| 单腿站立 | 14.5s | 「心里数到 10」就是真的 10 秒 |
| 肩前屈上举 | 7.0s | 举 2 → 停 2 → 放下 3 |

体检脚本会把标签里的「停 N 秒 / 保持 N 秒 / 数到 N」抓出来，量这一段里姿势
真正不动的最长时间，短了就报错。

代价是列表页的缩略图上，一个 14 秒的循环有 10 秒是不动的，看着像卡住。
所以缩略图走一条**按运动量重新分配时间**的重映射（`figure.js` 的 `warp`）：
静止段快速走过，动的部分照常，4 秒内把整个动作演一遍。
**只影响缩略图 —— 动作详情页仍然是真实节奏。**

### 改完数据要跑体检

```
node tools/check-figure.js          # 只报问题
node tools/check-figure.js --table  # 连关节角度表一起打出来，给治疗师逐帧复核
```

检查项：关节角有没有超出生理范围、脚有没有陷进地面或整个人悬空、
坐着的时候屁股在不在椅面上、手会不会掉到椅面以下（撑到地上）、
声明了扶扶手的手是不是真的够到了横杆、单腿站立时重心线有没有落在支撑脚上、
阶段条 `phases` 是不是递增并覆盖 0～1、**文字里承诺的「停 N 秒」动画有没有真的停够**、
手部动作的腕/卷曲/分开/拇指是否在范围内、握拳时指尖有没有落在掌心里。
**这些都是「照着练会出事」的错误，必须全绿才能发。**

### 手部特写

握拳伸展和腕关节屈伸是特写，比例和全身不一样（单位换成掌宽），所以有单独的手部视图。
它们也是关节角驱动的：

| 字段 | 含义 | 范围 |
|---|---|---|
| `wri` | 腕，+ 背伸 / − 掌屈 | −78 ~ 72 |
| `curl` | 手指卷曲：0 完全伸直、1 完全握拳、负数是掌指关节过伸 | −0.28 ~ 1 |
| `spread` | 五指分开 | 0 ~ 1 |
| `thumb` | 拇指：0 外展伸直、1 横过掌心 | 0 ~ 1 |

一个 `curl` 驱动三个关节，比例取自握拳时各关节的实际屈曲角（掌指 88°、近节指间 105°、
远节指间 72°），小指侧增益略大 —— 握拳本来就是从小指先卷起来的。

两个视角：
- `handView: 'palm'` 掌面视图，手指朝上。**握拳伸展用这个** —— 张开是五指散开、握拳是
  手指折过来盖住掌心，一眼认得出。侧视图做不到，四根手指会叠在一起。
  屈曲让手指朝观察者转，投影上就是缩短 + 往下落，所以指尖最后正好落在掌心里。
- `handView: 'side'` 桡侧视图，前臂垫在桌面上。**腕关节屈伸用这个** —— 这个动作的全部
  信息就是手腕上下摆的角度，必须侧着看。

原来的 `images/mv/grip.gif` / `wrist.gif`（167 KB）已经删掉。**至此 14 个动作全部是矢量的，
包体里不再有任何动画素材。**

## 升降级

练完每个动作要回答一句：**很轻松 / 有点吃力 / 做不到或疼**。

- 连续 2 次「很轻松」→ 先加组数；加到上限再升一档（阶梯见 `utils/library.js` 的 `LADDER`）
- 「有点吃力」→ 保持
- 「做不到或疼」→ 当场减组数或退一档；连续 3 天 → 提示就医

阶梯顺序是有讲究的：**先加量（安全），再减支撑（难度真正上升），最后才加幅度和速度。** 反过来做容易摔。

## 合规边界

v1 的 `utils/milestones.js` 写着「不算分、不分级、不下结论 —— 那属于功能评定，是医疗判断，
软件不能做」。**这个立场 v2 原样守住**，新增的快筛不能把它破掉：

- 界面上不出现分数、不出现分期。M/H 只用来筛内容
- 措辞是「按你勾的情况筛出来的」，不是「你的处方是」
- 不评估疗效、不做在线问诊、不生成治疗方案
- 每条剂量仍然标注公开指南出处

**上线前必须做的一件事：** 动作库、剂量、停止信号、代偿判定，要有康复治疗师逐条过一遍并签字留档。
v2 新增了站立与步行内容（v1 刻意回避了这块），跌倒风险必须由专业人把关。
`pages/about` 里写清楚了这部分的四个前提条件。

## 不同分辨率

（这一套 v1 做得很扎实，原样保留）

- 布局一律用 `rpx`，按屏宽等比
- `app.js` 按屏宽算字号系数写进 `--fs`，小屏放大、大屏收一点，让正文的**物理大小**接近一致；
  所有字号写成 `calc(32rpx * var(--fs))`
- 图片用 padding-top 百分比撑比例，不依赖 `aspect-ratio`
- 底部留了 `env(safe-area-inset-bottom)`
