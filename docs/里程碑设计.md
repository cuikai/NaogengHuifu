# 里程碑设计

> 回答一个具体问题：**进步用什么衡量？里程碑从哪儿来？**

## 结论：用改良 Barthel 指数（MBI）的条目

不用自己编里程碑。国际通用的日常生活活动能力量表已经把"恢复"
拆成了 10 件**患者和家属都听得懂的生活能力**——这正是我们要的东西。

### 10 个条目

| # | 条目 | 说成人话 |
|---|---|---|
| 1 | 进食 | 能自己把饭送进嘴里 |
| 2 | 洗澡 | 能自己洗澡 |
| 3 | 修饰 | 能自己洗脸、刷牙、梳头 |
| 4 | 穿衣 | 能自己穿衣服 |
| 5 | 大便控制 | 能控制大便 |
| 6 | 小便控制 | 能控制小便 |
| 7 | 用厕 | 能自己上厕所 |
| 8 | 床椅转移 | 能自己从床上挪到椅子上 |
| 9 | 平地行走 | 能在平地上走 |
| 10 | 上下楼梯 | 能上下楼梯 |

每个条目按独立程度分级：**完全依赖 → 大量帮助 → 中等帮助 → 少量帮助 → 完全独立**。

### 为什么这是正确的里程碑来源

1. **它衡量的是"能不能生活"，不是"练了多少次"**
   卒中康复最摧毁人的是"进步不可见"——练了三个月手还是抬不起来。
   而"这周能自己拿杯子了"是看得见的。

2. **每一次分级跃迁就是一个天然里程碑**
   从"需要大量帮助"到"需要少量帮助"，是真实的、可庆祝的进步。
   不需要我们发明任何东西。

3. **康复师看得懂**
   MBI 是临床常规量表。用它做里程碑，意味着家属记录的东西
   可以直接和医生、康复师对话，而不是一套只有我们自己懂的私有指标。

4. **授权干净**
   原始 Barthel 指数 1965 年发表，属公有领域；改良版中文量表在国内
   公开资料中广泛流传。

## 关键设计约束

### 评定必须由人做，不能由软件做

MBI 是**评估量表**，让软件自动打分就越过了[安全边界](安全边界.md)——
那是功能评定，属于医疗判断。

正确做法：

- 软件只**记录**里程碑达成事件，不计算总分、不做分级判断
- 达成由**康复师在复诊时确认**，或至少标注为"家属自述"
- 界面上不出现总分、不出现"恢复良好/较差"这类结论

### 展示为事件，不展示为分数

```
✅  能自己用患侧手拿起水杯      8月11日 · 王治疗师确认
✅  能扶着床沿自己坐起来        7月26日 · 王治疗师确认
⚪  下一个目标：扶着扶手走 5 步   和康复师一起定的
```

而不是：

```
❌  Barthel 评分：45 → 60 分（中度依赖）
```

前者是鼓励，后者是评定。

## 累计值必须只增不减

首页的主数字用**累计量**，不用连续打卡天数。

卒中患者**一定会漏练**——感冒、情绪低落、家属加班、天气不好。
任何 streak 机制在第一次断裂时都会摧毁动机，而且断得越晚摧毁得越彻底
（"我连了 47 天，断了，算了"）。

> 累计数只会往上走。它没有失败态。

## 相关量表（了解即可，本项目不使用）

| 量表 | 用途 | 为什么不用 |
|---|---|---|
| Brunnstrom 六阶段 | 运动功能恢复分期 | 需专业判断，属第三层 |
| mRS 改良 Rankin | 整体结局分级 | 是结局评定，不是过程激励 |
| FIM 功能独立性measure | 比 MBI 更细 | 有版权限制，且过于复杂 |
| NIHSS | 卒中严重程度 | 急性期评估，与居家无关 |
